# 大模型如何赋能科研工作台（方案）

结合 OpenAI / Google DeepMind / Anthropic / 微软 Research 等「研究型产品」常见做法：不是做一个万能聊天窗，而是把模型嵌进**科研对象工作流**里。

## 1. 大厂研究室常见范式（可借鉴）

| 范式 | 含义 | 对应你的模块 |
|------|------|-------------|
| Context-grounded copilots | 回答必须锚定本地文献/笔记/实验，而不是空聊 | 文献 AI 精读、今日 brief |
| Tool-using agents | 模型可调用检索、打开文件、写结构化字段 | 下一步：检索文献库、改笔记字段 |
| Memory & artifacts | 长期记忆是「稿件/主张/证据」，不是聊天记录 | Claim–Evidence、投稿事件 |
| Eval loops | 每次建议可验收（是否生成可执行 Next Action） | 今日建议、实验下一步 |
| Human-in-the-loop | 只提议不擅改；用户确认后写入 | AI 结果「追加到笔记」 |
| Local-first + BYOK | Key 用户自带，数据默认本地 | 设置 SK / Base URL |

## 2. 推荐分三期落地

### Phase A（已具备雏形）
- 设置中配置 **SK + Base URL + Model**（OpenAI 兼容）
- 文献：摘要 / 批判 / 关联课题 / 补笔记
- 今日：基于任务/文献/项目上下文的简短建议

### Phase B（高价值）
- **文献 RAG**：对 PDF 文本块建本地索引（hash + chunk），问答带来源页码
- **投稿助手**：根据审稿意见生成回复提纲（不自动提交）
- **实验助手**：从 Run 日志提炼失败原因与下一组消融建议
- **双向关联建议**：想法 ↔ 文献 ↔ 项目 自动推荐链接

### Phase C（研究室级）
- 多 Agent 编排：文献扫描 / 缺口检测 / 周报生成（限预算、可暂停）
- 评估集：固定 20 篇论文 + 标准问题，回归模型质量
- 可选本地模型（Ollama）与云端模型路由：隐私数据走本地，写作润色走云端

## 3. 产品原则（避免做成玩具）

1. **先对象后对话**：每次 AI 都挂在 Paper / Project / Submission 上  
2. **可追溯**：输出带来源（页码、笔记字段、Run id）  
3. **可写回**：一键写入笔记/下一步，而不是只展示  
4. **可关闭**：无 Key 时功能降级，不阻断主流程  
5. **成本可控**：默认短上下文；长 PDF 先摘要再精读

## 4. 安全

- Key 仅存本机 SQLite；API 只返回脱敏 hint  
- 不默认上传生活线数据  
- 导出 ZIP 时提醒包含密钥字段（可后续做导出脱敏开关）
